## Product decision

LaunchDeck layouts use ordered items plus integer tile spans. A shared deterministic first-fit engine computes responsive row/column placements; absolute coordinates are not persisted. Initial editor presets are 1×1, 2×1, and 2×2.

Configuration v2 contains stable page/item IDs, a default page, global layout settings, and named page item collections. Existing flat configs normalize in memory to one Home page and are only written as v2 on explicit save.

## Projects

- Layout Platform: schema v2, migration, atomic persistence, parser parity, placement, and automated invariants.
- Widget Experience: variable-span renderer, responsive sizing, pages, focus navigation, runtime hardening, then manual Game Bar acceptance.
- Live Grid Editor: three-pane preview, naming/movement/resizing, undo/redo, pages/layout controls, automated hardening, then manual usability acceptance.
- Delivery & Quality: Linear workflow, CI/review evidence, automated integration/release candidate, then final manual release approval.

## Dependency policy

- Layout schema blocks the layout engine.
- The automated layout engine gate blocks widget/editor implementation.
- Manual config migration does not block widget/editor agentic work.
- Widget/editor manual acceptance follows their automated hardening gates.
- Automated release readiness depends on automated gates only.
- Final release acceptance depends on the automated release candidate plus every project manual gate.

## Completion evidence

Implementation issues record exact commands/CI checks, results, commit state, skipped boundaries, and follow-ups before In Review. Scope-expanding review feedback becomes a sub-issue and blocker. Manual failures become Bug sub-issues; fixes are not performed inside acceptance issues.
